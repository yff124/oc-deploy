# 部署排错手册（6个实测卡点）

> 全部为 2026-10-22 真实安装过程中遇到的问题。
> 每一条都标注：现象 / 原因 / 解法 / 客户会怎么描述它。

---

## 卡点1：Node 版本不对（最高频，占失败的大头）

**客户会这样说**：
> "装到一半一堆红字" / "说我的版本不行" / "照教程做了还是报错"

**真实现象**：
```
ERROR: Node.js v22.13.1 is not supported
或安装后运行时报 node:sqlite 相关错误
```

**原因**：
OpenClaw 要求 **Node 24.22.1+ 或 26.12.1+**。
网上大量教程写"Node 18+"，这是**过时且错误**的。

官方源码里的真实检查（install.sh 第128行）：
```
Node <version>: node:sqlite truncates TEXT at embedded NUL (nodejs/node#61954);
use 24.22.1+/26.12.1+ or a build with the fix
```
旧版 Node 的 sqlite 模块有截断 bug，会导致数据损坏。

**⚠️ 特别注意**：
- Node **25.x 不兼容**（不在支持列表内）
- Node 24.21 不行，**24.22 才行**
- Node 26.11 不行，**26.12 才行**

**解法**：
```bash
# 有 nvm 的话（推荐）
nvm install 26
nvm use 26
nvm alias default 26     # 设为默认，否则新终端又变回旧版

# 验证
node -v      # 应显示 v26.12.x 或更高
```

**给客户的一句话**：
> "不是你的问题，是教程写错了。这个工具要求 Node 24.22 以上，网上写 18+ 的教程都会失败。"

## 卡点2：装了 nvm 时，官方安装器直接中止

**客户会这样说**：
> "跑安装命令，它停住了，说什么 nvm"

**真实现象**：
```
· Node.js v22.13.1 found, upgrading to a supported version
! Existing nvm detected; no compatible Node.js runtime is available
Load your existing nvm in your shell, then run:
  nvm install 26
  nvm use 26
✗ Installation stopped without changing Node.js
```

**原因**：
安装器检测到 nvm 后，**为了不破坏用户的版本管理，会主动放弃自动升级**，直接退出。
这不是 bug，是设计。但对新手来说就是"装不上"。

**解法**：
必须先手动切到 Node 26，**再**运行安装器：
```bash
source ~/.nvm/nvm.sh     # 或 source ~/.zshrc
nvm install 26
nvm use 26
nvm alias default 26
npm install -g --allow-scripts=openclaw,@google/genai,esbuild,koffi,protobufjs openclaw@latest
```

**给客户的一句话**：
> "你电脑上装了 nvm，官方安装器遇到它会主动停下。我先帮你切到 Node 26，再装。"

## 卡点3：npm 脚本授权不全，依赖装不完整

**客户会这样说**：
> "装完了但是用不了" / "提示缺东西"

**真实现象**：
```
npm warn install-scripts 4 packages have install scripts not yet covered by allowScripts:
npm warn install-scripts   @google/genai@2.27.0 (preinstall: ...)
npm warn install-scripts   esbuild@0.28.2 (postinstall: node install.js)
npm warn install-scripts   koffi@3.3.2 (install: node ./cnoke.cjs ...)
npm warn install-scripts   protobufjs@7.6.6 (postinstall: ...)
```

**原因**：
新版 npm 默认**不执行依赖包的安装脚本**（安全策略）。
如果不授权，`esbuild`（构建工具）、`koffi`（原生模块）等不会正确编译，程序运行时报错。

**关键细节**（我实测踩到的）：
- 只授权 `openclaw` → 会提示还缺 4 个
- 只授权那 4 个 → 会提示还缺 `openclaw`
- **必须一次性全部授权，共 5 个包**

**解法**：
```bash
npm install -g --allow-scripts=openclaw,@google/genai,esbuild,koffi,protobufjs openclaw@latest
```
> 注意：`--allow-scripts=` 后面用**逗号**连接，不能有空格。

**给客户的一句话**：
> "这是 npm 新的安全策略，要把 5 个依赖一次性授权，我帮你写好命令了。"

## 卡点4：TAR_ENTRY_ERROR 满屏红字，其实是正常警告

**客户会这样说**：
> "装的时候全是 error，是不是失败了？"

**真实现象**：
```
npm warn tar TAR_ENTRY_ERROR ENOENT: no such file or directory,
  open '.../dist/control-ui/assets/locale-config-hints-de-xxxx.js'
```

**原因**：
npm 打包时的文件路径处理问题，属于**上游打包瑕疵**。
它是 `warn` 级别，**不影响功能**。

**判断方法**：装完跑一下 `openclaw --version`，能出版本号就是成功了。

**解法**：忽略。如果确实有功能异常，重装一次：
```bash
npm cache clean --force
npm install -g --allow-scripts=openclaw,@google/genai,esbuild,koffi,protobufjs openclaw@latest
```

**给客户的一句话**：
> "红色警告不用管，只要最后能出版本号，就是装好了。"

## 卡点5：没有 systemd 时 gateway start 失败

**客户会这样说**：
> "启动不了，说什么 service disabled" / "云服务器上起不来"

**真实现象**：
```
Gateway service disabled.
Tip: openclaw gateway install
Tip: systemd user services are unavailable; install/enable systemd
     or run the gateway under your supervisor.
Tip: If you're in a container, run the gateway in the foreground instead
```

**原因**：
`openclaw gateway start` 依赖系统的服务管理器（Linux 的 systemd / macOS 的 launchd / Windows 的服务）。
以下环境没有或无法使用：
- Docker 容器
- 部分云服务器（精简系统）
- WSL 某些配置
- 权限受限的用户环境

**解法**：改用前台运行（放后台）：
```bash
nohup openclaw gateway run > ~/.openclaw-gateway.log 2>&1 &
echo $! > ~/.openclaw-gateway.pid

# 等待并验证（约 10 秒）
sleep 10
curl http://127.0.0.1:18789/health
# 期望：{"ok":true,"status":"live"}
```

**停止**：
```bash
kill $(cat ~/.openclaw-gateway.pid)
```

**给客户的一句话**：
> "你这是容器环境，没有系统服务，我改用后台进程方式跑，一样能用。"

## 卡点6：令牌显示 REDACTED，以为没生成

**客户会这样说**：
> "要输 token，但我查出来是这个 `__OPENCLAW_REDACTED__`"

**真实现象**：
```bash
$ openclaw config get gateway.auth
{
  "mode": "token",
  "token": "__OPENCLAW_REDACTED__"
}
```

**原因**：
这是**安全设计**——命令行输出可能被截图、被日志记录，所以故意打码。
**令牌是真实存在的**，只是不在终端显示。

**解法**：直接读配置文件：
```bash
# Linux / macOS
python3 -c "import json;print(json.load(open('$HOME/.openclaw/openclaw.json'))['gateway']['auth']['token'])"

# 或者用我脚本里带的命令
bash 一键部署.sh --token

# Windows PowerShell
(Get-Content "$HOME\.openclaw\openclaw.json" -Raw | ConvertFrom-Json).gateway.auth.token
```

**给客户的一句话**：
> "打码是正常的，令牌在配置文件里。我帮你取出来了。"

## 附：通用排错三板斧

客户报任何问题，按这个顺序问：

### 第一板斧：跑自检
```bash
openclaw doctor
```
它会直接把问题指出来，并给出修复命令（多数带 `--fix`）。

### 第二板斧：看状态
```bash
openclaw gateway status
```
重点看三行：
- `Gateway: bind=..., port=...` → 端口对不对
- `Connectivity check: ok` → 通不通
- `Listening: *:18789` → 在不在监听

### 第三板斧：看日志
```bash
# 服务日志
tail -50 ~/.openclaw-gateway.log

# 或应用日志
tail -50 /tmp/openclaw/openclaw-$(date +%Y-%m-%d).log
```

**90% 的问题，跑完 doctor 就能定位。**
